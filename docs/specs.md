**Что мы делаем?**

- Time-series database, вдохновленная внутренней структурой Prometheus. 

**Скоуп работ** 

реализация движка базы данных + хранилища на одной ноде с минимальным набором фич.

- Хранение, чтение, удаление данных, ориентированных на следующую структуру (__timestamp__(ulong), __series__(string), __labels__(опционально, set(string)), value(float64)).
- Повторение структуры TSDB - лог операций, нарезанных на части, который со временем флашится на диск и упаковывается (по некоторому правилу) в блоки.
- Поддержка базовых операций - вставка сэмплов с лейблами по конкретным меткам времени, поиск метрик за заданный период с конкретными лейблами, удаление метрик за конкретное время по лейблам.

**MVP**

_MVP бьётся на 3 блока:_ 

Построение структуры хранилища: 

- В первой итерации исключаем WAL, репликацию, шардирование
- Ориентируемся на стандартную структуру, воспринимаем однопоточно (пока что)
- Исключая WAL, пока исключаем crash-recovery. 
- Повторяем структуру чанков в памяти - posting индексы, хранений серий в памяти, label matching и прочее 
- Возможно откинем промежуточный вариант чанков в mmap диске, если не будем успевать. - будем писать сразу на диск (ака как в lsm-дереве)
- Основная задача: воссоздать структуры на диске, чтобы был фундамент, на котором можно дальше строить фичи. 

Выполнение операций:

- Запись списка значений по вариации следующеего интерфейса: (timestamp, [(series, labels, value)])
- Удаление [t0, t1] промежутка из базы для конкретного series + labels
- Получение значений метрик за [t0, t1] для конкретного series + labels (по операции =)

Поддержка базы в эффективном состоянии: 

- Флаш чанков/ин-мемори чанков в блок на диск по определенному ретеншену (ин-мемори обычно по преодоелнию временного промежутка + набору чанков)
- Бамп блоков на диске. (Опционально, если будем успевать).

**Явно выкидываем (в порядке от *возможно придется* сделать до *точно не придется* делать)**
* - WAL в первой итерации (придется писать для репликации)
* - Crash-recovery (не успеем, только если не будет обязательно)
* - Сжатие внутри блоков (если только не простое сжатие aka lz77, но надо порисерчить, не сломает ли это асимптотику)
* - Убиваем до простого состояния мультитрединг - пытаемся сделать его как можно проще, чтобы не выстрелить себе в ногу
* - MMAP в промежуточном состоянии (если будет просто и будет желание)
* - Сложные запросы (операторы, кроме равно, PromQL-like операторы, мержд метрик)
